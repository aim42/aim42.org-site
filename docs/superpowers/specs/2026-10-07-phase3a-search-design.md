# Phase 3a, part 3: search

Design spec, 2026-10-07. Status: **written from the request without a design
discussion**; decisions marked **[D]** were taken by the author and are open for
review. Parent spec: `2026-10-07-method-reference-merge-design.md`. Builds on
`2026-10-07-phase3a-navigation-pages-design.md` (search button in the header).

## 1. Goal and scope

Readers find any pattern or page by typing a few letters. Requested by the project
owner: lunr.js incremental search in a popup, Cmd-Enter, Tab and arrow navigation in
the results, and a results page.

Out of scope: search analytics, search in the PDF whitepaper, fuzzy "did you mean".

Copy rule: no dashes as sentence punctuation in visible text.

## 2. What the reader gets

### 2.1 Popup

- Opens from the search button in the header, or with `/` or `Cmd-K` (`Ctrl-K` off
  macOS) anywhere on the site, unless the focus is in a text field. **[D]**
- A modal `<dialog>` with one input and a result list below it. Results update as the
  reader types (from the second character, debounced 100 ms), at most 8 results.
  **[D]**
- Each result: title, a label (phase name for patterns, "Glossary" for terms, section
  title for other pages), and one line of context (the pattern's intent, the page's
  lede, or the term's definition), with the matched words highlighted.
- Below the list: "Show all N results" linking to the results page.
- Keyboard **[D]** (the request named Cmd-Enter, Tab and arrows; their meaning is the
  author's reading):

  | Key | Effect |
  |---|---|
  | ↓ / Tab | next result (wraps to the first) |
  | ↑ / Shift-Tab | previous result (wraps to the last) |
  | Enter | open the selected result; with none selected, the first |
  | Cmd-Enter (Ctrl-Enter) | open the results page for the current query |
  | Esc | close the popup, focus returns to the search button |

  Focus stays in the input; the selection is announced through the combobox pattern
  (`role="combobox"`, `aria-controls`, `aria-activedescendant`, results as
  `role="listbox"` / `role="option"`), as in the WAI-ARIA Authoring Practices.
- No results: "No matches for “…”" and a link to the Patterns index.

### 2.2 Results page

- `/search/?q=<query>`: the query in an input at the top, all matches below with the
  same title, label and context line, grouped in one ranked list. **[D]**
- Typing updates the list and the URL (`history.replaceState`), so a results page can
  be bookmarked and shared.
- The page is a plain `GET` form, so without JavaScript the header search button still
  leads here; the page then says that search needs JavaScript and links to the
  Patterns index. **[D]**
- Uses `aim42-page`; it is not listed in the navigation.

## 3. Index

- **Source:** `/assets/search.json`, generated by Jekyll from a Liquid template at
  build time. **[D]** One entry per document:
  - every pattern: `title`, `url`, `kind: pattern`, `label` (phase title), `context`
    (intent, plain text), `body` (plain text of the page body);
  - every page listed in the navigation, the phase pages and `/patterns/`: `kind: page`,
    `label` (section title), `context` (lede, else first paragraph), `body`;
  - every glossary term: `kind: term`, `url` `/glossary/#<id>`, `context` (definition).
- **Not prebuilt [D]:** the browser builds the Lunr index from that JSON when the popup
  first opens (or the results page loads). With about 130 documents this takes well
  under 100 ms, and the site needs no Node build step. quality.arc42.org prebuilds its
  index with Node; aim42 does not need to.
- **Fields and boosts [D]:** title 10, context 4, body 1; each typed word also matches
  as a prefix (`term*`) so results appear while a word is still incomplete; English
  stemming and stop words (Lunr defaults).
- **Lunr:** version 2.3.9 (MIT), vendored as `assets/js/vendor/lunr-2.3.9.min.js` with
  its licence header; no CDN at runtime. **[D]**
- **Loading:** Lunr and the JSON load only when the reader opens the search, so pages
  do not get slower.

## 4. Components

| File | Purpose |
|---|---|
| `assets/search.json` (Liquid) | The documents |
| `assets/js/vendor/lunr-2.3.9.min.js` | Lunr |
| `assets/js/search.js` | Loading, index, query, rendering, keyboard; shared by popup and results page |
| `_includes/aim42/search-dialog.html` | The `<dialog>` markup, included by `aim42-base` |
| `_pages/search.md` | Results page (`/search/`) |
| `_sass/components/_search.scss` | Popup and results styles |

`assets/js/search.js` is plain JavaScript (no build step, no framework), loaded with
`defer` on every page; it fetches Lunr and the JSON on first use.

## 5. Tests

- Site tests (Ruby, existing suite):
  - `search.json` is valid JSON; it contains every pattern, every navigation page and
    every glossary term exactly once; every `url` resolves to a built page (and
    anchor for terms);
  - the dialog markup is on every aim42 page: input with `role="combobox"`, listbox,
    labels; the header search button is visible and links to `/search/`;
  - `/search/` builds, has a `GET` form with input `q`, and a no-JavaScript notice.
- Browser tests **[D]**: Playwright, run in the `mcr.microsoft.com/playwright` image
  against the built site, new target `make e2e` and a CI step:
  - typing "strang" lists Strangler Approach first; "stakeholder" lists Stakeholder
    Interview and Stakeholder Analysis;
  - ↓, Tab, ↑, Shift-Tab move `aria-activedescendant` and wrap; Enter opens the
    selected result; Cmd/Ctrl-Enter opens `/search/?q=…`; Esc closes and returns
    focus to the button; `/` and Cmd/Ctrl-K open the popup, but not while typing in
    the results page input;
  - the results page shows all matches for `?q=`, and typing updates the URL;
  - no console errors on the home page, a pattern page and `/search/`.
- Visual check at 375 and 1280 px: popup and results page.
